# Chain-of-Thought Fine-Tune — Модель думает как архитектор
*Captured: 07.04.2026*

---

## Проблема которую это решает

Обычный fine-tune учит модель **что** делать. Она запоминает паттерны кода, правила, синтаксис. Но она не знает **почему** именно так — не умеет рассуждать как архитектор.

Если модель не понимает логику — она применяет правила механически и ломается на нестандартных ситуациях.

---

## Решение — Chain-of-Thought датасет

Каждый пример в датасете содержит не только вопрос и ответ, но и **цепочку рассуждений**:

```json
{
  "instruction": "Как хранить состояние которое нужно в нескольких компонентах?",
  "thinking": "Смотрю на архитектуру. Данные меняются в нескольких местах — значит нужен единый источник правды. У нас паттерн: всё через lib/data, компоненты никогда не пишут напрямую в JSON. Значит создаём функцию в data layer, компоненты только вызывают её.",
  "output": "Создай функцию в lib/data/[модуль].ts. Компоненты импортируют только эту функцию. Никогда не читай/пиши JSON файлы напрямую из компонента."
}
```

```json
{
  "instruction": "Баг: компонент не обновляется после изменения данных.",
  "thinking": "Первое — проверить источник данных. Если данные приходят из lib/data — проверить что функция возвращает новый объект, а не мутирует старый. Если state локальный — проверить что setState вызывается с новой ссылкой. Второе — проверить что нет stale closure в useEffect.",
  "output": "1. Проверь что loadX() возвращает новый массив/объект. 2. Проверь зависимости useEffect. 3. Если мутация — замени на spread: {...old, field: newValue}."
}
```

---

## Почему это решает проблему персистентной памяти

Сейчас: каждый новый чат — объясняешь правила заново. "У нас pull-pool workflow, данные только через lib/data, никогда напрямую..."

После fine-tune: эти правила **прошиты в веса модели**. Она просто знает. Как опытный разработчик который год работает в проекте — не потому что прочитал доку, а потому что это стало инстинктом.

## Что записывать в датасет

### 1. Архитектурные решения
```json
{
  "instruction": "Куда добавить новый MCP tool?",
  "thinking": "MCP tools добавляются в три места обязательно — иначе super_admin не получит доступ. Это критическое правило из ARCHITECTURE.md...",
  "output": "1. app/api/mcp/lib/tools/ — реализация. 2. auth.ts → ALL_ADMIN_TOOLS. 3. lib/data/team.ts → ROLE_PRESETS."
}
```

### 2. Паттерны отладки
```json
{
  "instruction": "Deploy упал, pm2 crash loop.",
  "thinking": "Crash loop обычно означает что build упал но pm2 пытается рестартовать. Нужно остановить pm2, посмотреть логи build, починить, потом запустить заново.",
  "output": "pm2 stop iam-os && npm run build 2>&1 | tail -50 → найди ошибку → исправь → pm2 start."
}
```

### 3. Логические принципы
```json
{
  "instruction": "Как решить что должно быть в data layer vs в компоненте?",
  "thinking": "Правило единственной ответственности. Если логика нужна в двух местах — она в data layer. Если только в одном компоненте — можно локально. Но если затрагивает файлы/БД — всегда data layer.",
  "output": "Спроси: 'Это нужно где-то ещё?' Да → lib/data. Нет, но работает с файлами → lib/data. Только UI состояние → локально."
}
```

### 4. Уроки из реальных багов
```json
{
  "instruction": "Почему нельзя патчить Login.tsx через MCP пока приложение упало?",
  "thinking": "Когда Electron app падает — MCP сервер тоже умирает, потому что они в одном процессе. Нет приложения = нет MCP = нет доступа к файлам. Нужен внешний инструмент или ручное исправление.",
  "output": "Всегда держи fallback способ редактирования файлов (Cursor, VS Code) отдельно от MCP. MCP = удобство, не единственный путь."
}
```

## Pipeline

```
1. Скрипт собирает все источники выше
2. Claude API генерирует chain-of-thought для каждого примера
   (instruction + thinking + output)
3. Ручная проверка + фильтрация плохих примеров
4. JSONL датасет готов
5. Unsloth + QLoRA fine-tune на Qwen2.5-Coder 7B
6. LoRA адаптер ~200MB
7. Тест: модель решает архитектурные задачи без подсказок
```

## Drag & Drop UI для накопления

Экран Knowledge Base в iamrunner.ai позволяет:
- Перетащить любой файл (.md, .ts, .json, .pdf)
- Выбрать режим: RAG / Dataset / Both
- Приложение само генерирует chain-of-thought примеры через Ollama
- Добавляет в dataset.jsonl
- Когда накопилось достаточно → кнопка Fine-tune

Замкнутый цикл: работаешь → накапливается → дообучается → работает лучше.

## Долгосрочное видение

Модель знает:
- **Что** — паттерны кода, правила архитектуры
- **Почему** — логика за каждым решением  
- **Как думать** — цепочки рассуждений архитектора
- **Чего не делать** — реальные баги из истории проекта

Это не просто "AI который пишет код". Это AI который **думает как ты**.
